# Dr_Booking — mobile app

Expo (SDK 57) + expo-router + TypeScript (strict) client for the Dr_Booking REST
API in `../api`. Phase 5 delivers the foundation: scaffold, the glassmorphism
pastel design system, session + api client, the auth flow, and the first real
screen (Find Doctors).

## Stack (locked)

- Expo SDK 57, React Native 0.86, React 19 — runs in **Expo Go**
- expo-router v57 with **typed routes** (`.expo/types`, regenerated by `expo start`)
- TypeScript strict, ESLint (flat config, `eslint-config-expo`) + Prettier matching api/ style
- State: zustand (auth store) · Session secrets: **expo-secure-store** (never AsyncStorage)
- Push: expo-notifications (best-effort, registered after login; silent skip in Expo Go
  when no EAS projectId)

## Getting started

```bash
# 1. Start the API (repo root or api/)
cd api
npm i && npx prisma db push && npx tsx prisma/seed.ts && npm run dev   # http://localhost:3000

# 2. Start the app (separate terminal, from mobile/)
cd mobile
bun install            # or npm install
cp .env.example .env.local   # EXPO_PUBLIC_API_URL=http://localhost:3000
EXPO_PUBLIC_API_URL=http://localhost:3000 npx expo start
```

Scan the QR code with Expo Go (phone on the same Wi-Fi; use your machine's LAN
IP instead of `localhost` for a physical device). Seeded accounts (password

## Architecture laws (mirrors the repo master context)

- **One api client** (`src/lib/api.ts`): base URL from `EXPO_PUBLIC_API_URL`,
  bearer attach, envelope parse, typed `ApiError`, error-code → English map,
  401 → clear session + route to `/login`.
- **Session** in `expo-secure-store` under `auth.token` / `auth.user`,
  hydrated on boot behind the splash gate.
- **Scoping law**: the client never sends a `doctorId` for staff roles — the
  server scope wins. A 404 for someone else's resource is by design.
- **Time law**: business dates (`YYYY-MM-DD`) and times (`HH:mm`, IST) are
  passed through as plain strings — never `new Date(...)` timezone math.
- **Envelope**: `{ ok:true, data } | { ok:false, error:{ code, message } }` everywhere.
- **api/ is frozen** in mobile phases — API gaps go in the PR description.

## Design system — "glassmorphism pastel blue-purple"

- Full-screen diagonal gradient `#BFD9F2 → #C7E3EC → #CBC6E8` (`GlassScreen`)
- Translucent white glass cards: 50% alpha, radius 24, 1px white border,
  navy shadow blur 24 (`GlassCard`, `nested` for inner panels)
- Pill text fields with left icon + password toggle (`GlassTextField`)
- Primary CTA: full-radius pill, `#6EC1F5 → #4D9FDE` gradient, white semibold,
  blue glow, pressed/loading/disabled states (`PrimaryButton`)
- Navy secondary pill (`NavyButton`), glass/destructive tones (`GlassButton`)
- Translucent header with circular glass back button (`GlassHeader`)
- Status chips: CONFIRMED green · CALLED blue · COMPLETED gray-green ·
  CANCELLED red · NO_SHOW gray · PENDING orange (`StatusChip`)
- Typography scale (display/h1/h2/body/caption) + 4px spacing scale as tokens

**Review it in-app:** sign in (dev build) → Profile tab → _Design system demo_
(or the palette button on Find Doctors) → `app/demo.tsx` renders the whole kit.

## Known limitations (Phase 5)

- Booking is visible but disabled (`Booking opens in Phase 6`).
- Staff and admin areas are single placeholder screens (Phases 7–8).
- Doctor self-registration sends `name/phone/password/role` only — the API
  accepts no specialization fields at register (see PR "API GAP").
- No appointment reminders screen; push registration is fire-and-forget.
- `router.replace('/login')` after logout does not hard-reset the history
  stack (acceptable for Phase 5; revisit in Phase 6).
